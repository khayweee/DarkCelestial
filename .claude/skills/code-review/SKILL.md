# Skill: Code Review

Use this skill when reviewing a change, pull request, diff, or proposed implementation.

## Priorities

1. Correctness bugs.
2. Security, privacy, or data-loss risks.
3. Behavioral regressions.
4. Missing or insufficient tests.
5. Maintainability issues that create real future risk or ambiguity.
6. Clean code, SOLID principles, and style issues.

## Process

- Inspect the changed files and enough surrounding code to understand behavior.
- Focus on actionable issues.
- Avoid broad style feedback unless it blocks maintainability or correctness.
- If no issues are found, say so directly.

## Output

Lead with findings ordered by severity. Include file and line references where possible. Put questions and summary after findings.
